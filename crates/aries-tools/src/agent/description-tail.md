使用 Agent 工具时，通过 `mode` 参数选择要使用的智能体类型；若取值未匹配任何类型，则回退为 general。

何时不使用 Agent 工具：
- 若只是想读取某个确切的文件路径，直接用 Read 工具或 Glob 工具会更快；
- 若只是查找某个具体的符号定义（如 `class Foo`），直接用 Glob 工具会更快；
- 若只是在某个文件或 2-3 个文件内查找代码，直接用 Read 工具会更快；
- 与上面各智能体描述无关的其他任务。

使用注意：
- 始终提供一个简短的 `description`（3-5 个词）概括该智能体要做的事；
- 尽可能并行发起多个智能体以提升效率——在一条消息中放入多个 Agent 工具调用；
- 智能体完成后只会返回一条消息。返回结果对用户不可见；若要展示给用户，请你自己整理一份简明摘要回复；
- 返回结构中包含 `task_id`：提供该 `task_id` 时会复用同一个子智能体会话（保留先前的消息与工具输出），不提供则每次都是全新上下文；
- 明确告诉智能体你期望它编写代码，还是仅做研究（搜索、阅读、抓取等）；如可能，附上验证方式（如相关测试命令）；
- 若某个智能体的描述表明它应被主动使用，请尽量在用户未明确要求时也主动使用它，自行判断；
- 若用户要求“并行”运行多个智能体，你必须在一条消息中放入多个 Agent 工具调用。

编写 prompt：
子智能体看不到当前对话——把它当作一位刚走进房间的聪明同事来做简报：它没看过这段对话、不知道你已经尝试过什么、也不明白这个任务为何重要。
- 说明你想达成什么、以及为什么；
- 描述你已经了解到或已经排除的信息；
- 提供足够的周边背景，让它能自行做判断，而不是机械地执行一条狭窄的指令；
- 如果你只需要简短回复，请明确说明（例如“用 200 字以内汇报”）；
- 查询类任务：把确切的命令交给它；调查类任务：把问题本身交给它——当前提可能有误时，预设的步骤反而是累赘。

不要把“理解”外包出去。不要写“根据你的发现去修复这个 bug”或“根据调研去实现它”这类话——那是把综合分析推给了子智能体。你的 prompt 应当体现你已经理解了问题：包含文件路径、行号、以及具体要改什么。
