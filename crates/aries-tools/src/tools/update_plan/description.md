向客户端提供完整的执行计划，用于跟踪多步骤工作、多个交付项或用户要求的待办清单。简单的一步操作或纯问答通常无需调用；它只更新进度展示，不会执行条目中的任务。

- `items` 每次整体替换当前计划，不是追加或局部更新；应传入仍需展示的完整条目列表。传 `[]` 清空计划，所有条目均为 `completed` 时也会自动清空。
- 每项必填 `content`（要做的事，如“运行测试”）、`active_form`（执行时的展示文本，如“正在运行测试”）、`priority`（`high` / `medium` / `low`）和 `status`。前两项不能是空串或全空白。
- `status` 为 `pending`（未开始）、`in_progress`（进行中）或 `completed`（确已完成）。通常只保留一个进行中的条目；工具不校验该数量，也不会验证任务是否真正完成。
- 在步骤开始、完成或计划调整时更新；有阻塞或验证失败时保留未完成状态。无需为每次文件读写更新一次。
- 返回实际保留的 `items`；空列表表示计划已清空，不代表工具替你完成了工作。
