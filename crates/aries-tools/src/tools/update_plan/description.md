在执行任务的过程中，向客户端推送或更新当前的执行计划（plan）。这个工具用于让用户实时看到你正在做什么、做到哪一步了、还有哪些待办——类似 todo list / 任务进度跟踪。

## 何时使用

主动在以下场景使用：

- 复杂的多步骤任务——需要 3 个以上不同步骤或操作；
- 需要仔细规划、涉及多处改动的非平凡任务；
- 用户明确要求使用待办清单；
- 用户一次性给出多个任务（编号或逗号分隔）；
- 收到新指令后——立即把用户需求记录为待办；
- 开始执行某一步时——先把它标为 `in_progress` 再动手。

## 何时不使用

- 只有单一、直接的任务；
- 任务过于琐碎、跟踪它没有组织上的收益；
- 任务用不到 3 个简单步骤即可完成；
- 纯对话或信息性请求。

只有一件小事时，直接做即可，不要用本工具。

## 任务状态

- `pending`：尚未开始；
- `in_progress`：正在进行——**任意时刻只允许恰好一个**任务处于此状态；
- `completed`：已完成。

## 每个条目的两种描述形式

- `content`：祈使句形式，描述要做什么（例："运行测试"、"构建项目"）；
- `active_form`：进行时形式，执行时展示（例："正在运行测试"、"正在构建项目"）；
- 二者都必须非空。

## 行为

- 每次调用都会**整体替换**当前 plan，所以每次都要传入完整的条目列表；
- 当所有条目都为 `completed` 时，plan 会被自动清空；也可主动传入空数组 `items: []` 清空。

## 使用建议

- 第一次推送时把所有条目都设为 `pending`；开始执行某一步时把它改成 `in_progress` 再调一次；完成时改成 `completed` 再调一次。
- 完成后**立即**标记 `completed`，不要攒着一起标。
- 只有在真正完成时才标 `completed`；若有报错、阻塞或未完成，保持 `in_progress`，并另开一条待办描述待解决的问题。
- 不要为每个文件读写都更新一次 plan——在「步骤切换」时更新即可。
