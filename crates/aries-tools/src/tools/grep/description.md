在当前工作目录（包括已进入的 worktree）下递归搜索本地文件内容，用于根据函数名、报错文本或配置项定位代码。按文件名找路径用 `Glob`，读取已知文件用 `Read`，查询符号的语义定义或引用可用 `Lsp`。

- `pattern` 是逐行匹配的正则表达式，使用 Rust regex 语法；不支持跨行匹配、环视或反向引用。搜索字面文本时须转义正则元字符。
- `include` 是相对于工作目录的文件路径 glob，如 `src/**/*.rs`；它只过滤文件，不改变搜索根目录。默认跳过隐藏项并遵循 `.gitignore` 等规则，分别用 `hidden` 和 `respect_ignore` 调整。遇到二进制 NUL 字节会停止搜索该文件。
- `output_mode` 默认 `files_with_matches`，只返回匹配文件的相对路径，按修改时间从新到旧排序；`content` 返回匹配行和可选上下文；`count` 返回各文件的匹配行数，不是字符串出现次数。
- `case_insensitive` 默认 `false`。`content` 模式下，`show_line_numbers` 默认 `true`，行号从 1 开始；`context` 默认 0，表示匹配行前后各展示的行数。匹配行用 `:` 分隔，上下文行用 `-` 分隔。
- `limit` 默认 250，传 0 不限量：`content` 限制整个搜索的匹配行数（不计上下文），其余模式限制文件数。`content` 和 `count` 的结果顺序不固定；达到限额后仍保留已选匹配的后置上下文，其中再次命中的行也只作为上下文展示。
- 返回 `matches` 和 `truncated`；`truncated=true` 表示还有匹配被省略，应缩小 `include` / `pattern` 或提高限额后重查，没有分页游标。无结果只代表当前范围和过滤条件下未找到匹配。
- 不修改文件。遍历、读取或忽略规则解析失败会报错；`content` 模式下超长行或上下文超过 10 MiB 搜索缓冲区也会报错。
