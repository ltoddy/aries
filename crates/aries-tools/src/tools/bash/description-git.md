# 使用 git 提交改动

- 只有用户明确要求时才提交或推送；不要修改 Git 配置，不要创建无改动的空提交。
- 提交前查看 `git status`、已暂存与未暂存的 diff、近期提交风格。独立的只读检查可以并行；按具体文件路径暂存，检查暂存差异，创建提交，再检查状态，这些步骤必须顺序执行。
- 仅提交任务相关改动，保留用户已有工作，避免纳入密钥、凭据和无关文件；提交说明应简洁说明改动目的。多行说明须用保留字面内容的引用方式或消息文件传递。
- 优先创建新提交；只有用户明确要求时才 amend、跳过 hooks 或绕过签名。hook 失败时提交尚未成功，应修复问题、重新暂存并重新提交，不要因此 amend 前一个提交。
- `push --force`、`reset --hard`、`checkout .`、`restore .`、`clean -f`、`branch -D` 等破坏性操作须有用户明确授权；用户要求向 main/master 强推时先说明风险。
- 不使用需要交互的 `git add -i` 或 `git rebase -i`。推送会修改远程仓库；超时或响应丢失时先检查远程状态再决定是否重试。
