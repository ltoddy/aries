执行与结果：

- 新建时不自动继承主智能体对话或其他子智能体的上下文，须在 `prompt` 中提供目标、必要背景、相关路径、约束和交付要求。
- 复用时传入当前父会话中此前返回的原 `agent_id`，仍须填写 `name`；保持原 `name` 以沿用配置，在 `prompt` 中说明本次追问或后续要求及新增信息，无需重复原任务全文。询问此前做过什么时，要求依据已有上下文回答，不重新执行；涉及继续修改时，明确允许的改动范围。
- 子智能体从当前工作目录开始，与主智能体共享文件系统，没有自动隔离的工作副本；具有写入能力时，改动会直接影响这些文件。
- 调用等待子智能体完成，返回 `result`、子智能体标识 `agent_id` 和记录路径 `transcript_dir`。保留 `agent_id` 与任务、`name` 的对应关系，后续直接用原 ID 追问；不要自行生成 ID，也不能将其用于 `TaskOutput` / `TaskStop`。
- 返回内容是子智能体的汇报，不等于工作已通过验证；有疑问先复用原 `agent_id` 请其澄清。需要独立核验、精确审计，或原子智能体无法可靠回答时，再检查 `transcript_dir` 下的记录或相关文件；不要把读取记录当作普通追问的默认方式。向用户总结时区分汇报与验证结果，工具结果不会自动成为你的最终回复。
- 只有互不依赖、不会相互覆盖文件的任务才适合并行委派；不要并发调用同一个 `agent_id`，以免历史读写冲突。
