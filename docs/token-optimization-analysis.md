# Aries Token 消耗分析与优化建议

## 项目概述

Aries 是一个用 Rust 编写的命令行 AI Agent 工具，基于 `rig-core` 框架构建。它是一个终端交互式 AI 助手，支持丰富的工具集（文件读写、Shell 执行、搜索、LSP 等）和多种 Agent 类型。

---

## Token 消耗主要原因

### 1. 聊天历史无限增长
- **问题**：`chat_history` 随对话不断累积，每次调用 LLM 时通过 `.with_history(self.chat_history.clone())` 传递完整历史
- **影响**：所有之前的消息（包括工具调用的参数和结果）都会进入上下文
- **位置**：`src/agent/orchestrate.rs`
- **缺失**：没有设置最大消息数、滑动窗口或自动压缩机制

### 2. 缺少自动上下文压缩
- **问题**：`Compaction` Agent 类型已定义但从未在主循环中自动触发
- **影响**：长对话无法自动摘要，上下文持续增长
- **位置**：`src/agent/agent_type.rs`
- **现状**：Compaction Agent 仅在 Task 工具中可手动启动，但实际代码中并未调用

### 3. Grep 结果无上限
- **问题**：grep 工具的 `matches` 数组没有大小限制
- **影响**：在大型代码库中搜索常见模式时，可能返回数千条匹配，全部注入上下文
- **位置**：`src/tools/grep.rs`

### 4. CodeSearch 默认 Token 较高
- **问题**：`tokensNum` 默认 5000，范围 1000-50000
- **影响**：一次 code_search 调用可能向上下文注入多达 50000 个 token 的结果
- **位置**：`src/tools/codesearch.rs`

### 5. Batch 工具并行调用
- **问题**：支持最多 25 个并行工具调用（`.take(25)`）
- **影响**：如果每个调用都读取大文件，累积效果会导致大量 token 消耗
- **位置**：`src/tools/batch.rs`

### 6. 工具描述全量发送
- **问题**：每次请求都包含所有工具的定义和描述（15+ 个工具）
- **影响**：系统提示词 + 工具描述构成固定开销，每轮对话重复消耗
- **位置**：`src/tools/descriptions/*.txt`

### 7. 子智能体上下文开销
- **问题**：每次 Task 工具调用都创建全新 Agent 实例和会话
- **影响**：子智能体的完整响应作为结果返回给主智能体，直接加入主上下文
- **位置**：`src/tools/task.rs`

### 8. 最大轮数设置较高
- **问题**：`default_max_turns(200)`
- **影响**：复杂任务在长对话中会积累大量上下文
- **位置**：`src/agent/mod.rs`

## 现有的良好设计

| 机制 | 说明 | 位置 |
|------|------|------|
| Read 截断 | 默认限制 2000 行，每行截断到 2000 字符 | `src/tools/read.rs` |
| Bash 截断 | stdout 和 stderr 各截断到 200 行 | `src/tools/bash.rs` |
| Batch 限制 | 最多 25 个并行调用 | `src/tools/batch.rs` |
| 禁止 Batch 嵌套 | 防止递归爆炸 | `src/tools/batch.rs` |
| 系统提示词分离 | 按 Agent 类型分离，简洁明确 | `src/agent/prompts/*.txt` |

## 优化建议（按优先级排序）

### 高优先级

#### 1. 自动上下文压缩
- 监控当前 token 使用量，达到阈值时自动触发 Compaction Agent
- 将旧消息摘要替换为简洁总结
- 实现滑动窗口：保留最近 N 条消息，其余压缩

#### 2. Grep 结果限流
- 添加最大匹配数限制（如 100 条）
- 超出时提示用户缩小搜索范围

#### 3. 上下文窗口管理
- 添加基于 token 数的限制，接近模型上限时触发压缩
- 支持配置最大历史消息数

### 中优先级

#### 4. 工具描述优化
- 实现按需加载工具，而非每次全量发送
- 根据任务类型动态选择可用工具子集

#### 5. CodeSearch 默认值调整
- 降低默认 token 数（如从 5000 降至 2000）
- 添加结果摘要机制

#### 6. 子智能体响应摘要
- 子智能体返回时自动进行摘要，而非完整返回

### 低优先级

#### 7. 调整最大轮数
- 降低默认 `max_turns`（如 50-100）
- 支持用户自定义配置

## 预期收益

| 优化项 | 预期节省 |
|--------|----------|
| 自动上下文压缩 | 30-50%（长对话场景） |
| Grep 结果限流 | 10-30%（搜索场景） |
| 工具描述优化 | 5-15%（每轮固定开销） |
| 上下文窗口管理 | 20-40%（长对话场景） |
